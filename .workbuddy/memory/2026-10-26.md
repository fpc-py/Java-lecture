### 本轮修掉的真实缺陷（都是"只在真正启动时才暴露"那一类）

1. `OrderCompensateJob` 残留占位行 `Money.zeroIfNull()` → 删
2. `HttpInventoryClient` 多余方法 `unused()` + 未用 import → 重写
3. TCC 契约 `confirm/cancel` 只传 orderNo，实现里用 `DEFAULT_SKU=90001` 猜分支号 → 改为签名带 skuId；`StockSnapshot` 增 `priceCents`，价格回归库存域
4. `OrderPaidConsumer` 消费 `ORDER_PAID` 却调 `onPaid`（而 `onPaid` 正是该 Topic 的生产者）→ **消息回环**，删除，消费方移至 notify 服务
5. `ResultWrapAdvice` 把 `/internal/**` 也包成 `Result` → 内部 RPC 契约被污染，改为跳过
6. `EncryptTypeHandler` 上的 `@MappedTypes(String.class)` 一旦被全局注册会加密**所有** String 列 → 移除注解
7. `create_time` vs `created_at` 命名不一致（DDL 索引 + XML 排序 + Controller 白名单三处）→ 统一 `created_at`
8. `OrderQueryMapper.xml` 注释里含 `--`（注入 payload 的 SQL 注释符）→ XML 注释非法，SAX 解析失败；改用 `[MINUS][MINUS]` 并写明这个坑
9. monolith 缺 `spring-boot-maven-plugin` 的 `repackage` execution → 打出的不是可执行 jar；同时把 monolith（无 classifier）与 service（有 classifier=exec）的差异写进 pom 注释
10. Redisson 读 `spring.data.redis`，但 6 个服务 + monolith 都没配 → 全部补上 16379
11. outbox/死信表名与代码不一致（代码 `t_local_message`/`msg_id`/`reason`，DDL 写成 `t_outbox_message`/`biz_key`/`error`）→ DDL 重写对齐
12. MyBatis mapper 扫描：`scanBasePackages` 只影响组件扫描，**不影响** MyBatis scanner（后者只认 `AutoConfigurationPackages` = 启动类所在包），导致 `com.polaris.trade.mq.outbox.OutboxMapper` 找不到 → monolith 与 6 个服务全部加 `@MapperScan("com.polaris.trade")`（gateway 无 mybatis，不加）
